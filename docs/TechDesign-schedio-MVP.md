# Technical Design Document: Schedio MVP

## Overview
This document outlines the technical architecture for **Schedio**, a Chrome Extension built to turn highlighted text into Google Calendar events in under 5 seconds. The goal is a high-speed, 5-day sprint using a serverless, client-side-only architecture.

---

## Recommended Approach

### Primary Strategy: Plasmo + Gemini + Chrome Identity
Based on your "Just want it shipped" priority and $0 budget, we will build a **Manifest V3** extension using **Plasmo**.

*   **Why this works:** Plasmo handles the complex "Content Script UI" problem (Shadow DOM) automatically, allowing you to use Shadcn UI components without the host website's CSS breaking your modal.
*   **Time to MVP:** 5 Days.
*   **Cost:** $0 (Gemini Free Tier + Chrome Identity).

### Alternative Options Compared

| Option | Pros | Cons | Cost |
| :--- | :--- | :--- | :--- |
| **Plasmo (Recommended)** | Best-in-class React DX; handles Shadow DOM. | Slight abstraction over raw extension files. | $0 |
| **Standard Vite/CRXJS** | Standard tooling; very lightweight. | Manually managing UI injection and CSS isolation is slow. | $0 |
| **No-Code (Lovable)** | Extremely fast UI generation. | Difficult to handle Chrome-specific APIs (Identity/Context Menus). | $20+/mo |

## Tech Stack Specified

*   **Framework:** [Plasmo](https://www.plasmo.com/) (React 18 + TypeScript).
*   **Styling:** Tailwind CSS + [Shadcn UI](https://ui.shadcn.com/).
*   **AI Engine:** Gemini 1.5 Flash (Google AI Studio).
*   **Authentication:** Chrome Identity API (OAuth 2.0 Client ID).
*   **API Communication:** Standard Browser `fetch`.
*   **Icons:** Lucide React.

## Key Feature Implementation

### 1. The Capture Flow (Background Script)
When a user right-clicks highlighted text, the background script sends a message to the content script.

**Technical Trade-off:** We use `chrome.storage.local` to pass the captured text to ensure the modal has access to it immediately upon mounting.

### 2. LLM Parsing (Gemini 1.5 Flash)
We will use **JSON Mode** to ensure the output is programmable.

**System Prompt Strategy:**
```text
"You are a scheduling assistant. Extract event details from the user text. 
Return ONLY JSON with keys: summary, startDateTime, endDateTime, location, description.
Current time: [ISO_String]. If end time isn't mentioned, assume 30 mins after start."
```

### 3. Serverless Auth (Chrome Identity)
To stay $0 budget and backend-free, we use `chrome.identity.getAuthToken`.

*   **Setup:** You must create an OAuth Client ID in Google Cloud Console specifically for a "Chrome Extension" and whitelist your Extension ID.
*   **Manifest requirement:** 
    ```json
    "oauth2": {
      "client_id": "YOUR_GOOGLE_CLIENT_ID",
      "scopes": ["https://www.googleapis.com/auth/calendar.events"]
    }
    ```

## Important Limitations & Risks

1.  **API Key Exposure:** Since this is a client-side extension, the Gemini API key will be inside the code. 
    *   *Workaround:* For the MVP, this is fine for personal use. For public launch, move the Gemini call to a Cloudflare Worker (Free tier).
2.  **Date Context:** LLMs often struggle with "Next Tuesday" if they don't know today's date. 
    *   *Workaround:* Always inject the current date/time into the Gemini prompt dynamically.
3.  **Strict CSRF/CSP:** Some sites (like GitHub or Twitter) have strict security that can block external API calls from Content Scripts.
    *   *Workaround:* Always make the Gemini and Google API calls from the **Background Service Worker**, which is not restricted by the website's CSP.
